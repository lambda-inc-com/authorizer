# 多智能体工作流生成系统 - 系统概览

## 🎯 项目目标

基于多智能体架构实现一个智能工作流生成系统，能够：
1. 分析用户的自然语言需求
2. 自动生成符合规范的工作流JSON配置
3. 验证生成的工作流正确性
4. 支持错误修复和重试机制

## 🏗️ 架构设计原则

### 1. 单一职责原则
每个智能体只负责一个特定的任务：
- **RequirementAnalyzer**: 专门负责需求分析
- **WorkflowComposer**: 专门负责工作流组合
- **WorkflowValidator**: 专门负责工作流验证

### 2. 松耦合设计
- 智能体间通过消息总线通信，不直接依赖
- 使用共享状态管理器统一管理数据
- 支持智能体的独立测试和替换

### 3. 可扩展性
- 基于抽象基类的设计，易于添加新智能体
- 消息驱动架构，支持动态扩展功能
- 模块化设计，便于功能迭代

## 🧠 智能体设计详解

### RequirementAnalyzer (需求分析智能体)

**核心任务**: 将自然语言需求转换为结构化的节点需求列表

**关键设计**:
- 使用科学的提示词工程，确保输出格式标准化
- 内置节点类型知识库，提供准确的节点建议
- 支持复杂业务场景的分析和分解

**提示词策略**:
- 角色扮演: 将LLM定位为专业的工作流分析专家
- 结构化输出: 强制要求JSON格式输出
- 上下文丰富: 提供详细的节点类型信息

### WorkflowComposer (工作流组合智能体)

**核心任务**: 将节点需求组合成完整的可执行工作流

**关键设计**:
- 内置节点模板库，确保配置的准确性
- 数据流分析算法，自动建立节点连接关系
- 支持重试机制，根据验证反馈优化生成结果

**核心算法**:
- 节点依赖分析: 根据数据流确定执行顺序
- 配置补全: 基于模板自动补全节点配置
- 连接关系优化: 确保工作流的执行路径正确

### WorkflowValidator (工作流验证智能体)

**核心任务**: 全面验证工作流的正确性和可执行性

**验证层次**:
1. **结构验证**: 字段完整性、类型正确性
2. **配置验证**: 节点配置的完整性和正确性
3. **逻辑验证**: 连接关系、数据流一致性
4. **可执行性验证**: 循环检测、死链检测

**验证算法**:
- 图论算法检测循环引用
- 数据流分析验证引用路径
- 规则引擎验证业务逻辑

## 🔄 系统交互流程

```
1. 用户输入需求
   ↓
2. 需求分析智能体
   - 解析自然语言
   - 识别关键业务实体
   - 生成节点需求列表
   ↓ (共享状态更新)
3. 工作流组合智能体
   - 读取节点需求
   - 生成详细配置
   - 建立连接关系
   ↓ (共享状态更新)
4. 工作流验证智能体
   - 多维度验证
   - 生成详细报告
   - 提供改进建议
   ↓
5. 验证结果处理
   - 如果通过: 返回成功结果
   - 如果失败: 触发重试机制
   ↓
6. 重试机制 (最多3次)
   - 将错误信息反馈给组合智能体
   - 重新生成和验证
```

## 💡 核心创新点

### 1. 提示词工程
- **科学设计**: 基于认知科学原理设计提示词
- **结构化输出**: 强制JSON格式，确保结果可解析
- **上下文丰富**: 提供充分的领域知识和示例

### 2. 错误恢复机制
- **智能重试**: 基于验证反馈的智能重试
- **错误传播**: 详细的错误信息传递机制
- **渐进改进**: 每次重试都基于上次的错误进行改进

### 3. 状态管理
- **并发安全**: 使用asyncio.Lock确保状态一致性
- **版本控制**: 记录完整的生成历史
- **回滚机制**: 支持状态的回滚和恢复

## 🛡️ 质量保证

### 1. 多层验证
- **语法验证**: JSON格式和字段完整性
- **语义验证**: 业务逻辑和数据流正确性
- **可执行性验证**: 运行时错误预防

### 2. 错误处理
- **异常隔离**: 单个智能体异常不影响系统
- **优雅降级**: 部分功能失效时的备选方案
- **详细日志**: 完整的执行日志和错误追踪

### 3. 性能优化
- **异步架构**: 支持高并发处理
- **缓存机制**: LLM响应缓存减少重复调用
- **批量处理**: 支持多个工作流并发生成
